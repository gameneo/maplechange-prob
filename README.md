# 메이플체인지 확률 공개 · 검증

메이플체인지(메이플스토리 월드)가 게임 안에서 쓰는 **확률표 전부**와, 누구나 직접 돌려 볼 수 있는 **검증 스크립트**입니다.

| 파일 | 내용 |
|---|---|
| `확률표.md` | 주문서 성공·파괴율 · 몬스터 드롭 확률(배율 적용) · 보스 보상 확률 — 사람이 읽는 표 |
| `확률표.en.md` | 위 표의 영어판(이름·머리말만 영어, 숫자는 같음 — 원본은 한국어판) |
| `확률표.zh-tw.md` | 위 표의 번체(대만)판(이름·머리말만 번체, 숫자는 같음 — 원본은 한국어판) |
| `tables/*.csv` | 위 표의 원본 칸(게임 데이터에서 그대로 뽑음) |
| `prob-table.txt` | 지문을 내는 정규 문자열 전체 |
| `FINGERPRINT` | 지금 표의 SHA-256 지문 |
| `probfp.cjs` | `tables`로 정규 문자열을 다시 만들어 지문을 계산 |
| `verify.cjs` | 주문서·황금 망치 한 번의 결과(commit-reveal)를 검증 |

## 1. 확률표가 게임과 같은지

```
node probfp.cjs
```

두 줄이 나옵니다. `mc-prob-scroll-v3 … sha256=…`(주문서 지문)이 게임 안 **[확률 공시] 창 맨 아래 두 줄**(64자리)과 같으면, 게임이 굴리는 주문서·캐시 주문서·슬롯 강화 확률과 보스 보상 초기화권 드롭 확률이 이 저장소의 표와 한 글자도 다르지 않다는 뜻입니다.
`mc-prob-v4 … sha256=…`(전체 지문 — 주문서 + 슬롯 강화 + 몬스터 드롭 + 나만의 사냥터 + 보스 보상)은 서버 기록과 이 저장소 `FINGERPRINT` 첫 줄로 확인합니다. 몬스터·보스 드롭 확률은 게임 안에서는 길라잡이 DROP LIST에 실효 확률로 보입니다.
표가 바뀌면(새 사냥터·보스·주문서) 지문이 바뀌고, 이 저장소도 같은 날 함께 바뀝니다.

정규 문자열 규칙(v4): 첫 줄 `mc-prob-v4` + 아래 줄들을 UTF-8 바이트 순으로 정렬해 줄바꿈으로 이음(끝 줄바꿈 없음). 주문서 지문 = 첫 줄 `mc-prob-scroll-v3` + `S|`·`T|`·`M|rare|` 줄만(같은 규칙) — `node probfp.cjs --scroll`로 전체 문자열.

| 줄 | 뜻 |
|---|---|
| `S|주문서|성공률%|파괴율%` | 주문서(캐시판은 효과가 같은 드롭판 값) · 파괴율 = 어둠은 실패했을 때, 백의는 바를 때마다(성공 다음 구간) — `tables/ScrollTable.csv` kind |
| `T|별|성공 기준|실패하면 별|시도 비용|돌려받기` | 슬롯 강화 그 별 시도 — 굴림(1~10000) ≤ 성공 기준이면 그 별, 아니면 0성 · 시도 비용 = 10만 × 2^(별−1) 메소 · 돌려받기 = 별 × 2^별 × 10만 메소 (`tables/SlotStarTable.csv` · `GameConfig` slotMaxStar·slotRateBp) |
| `C|dropRate|배율×1000` | 몬스터 드롭에 곱하는 배율 |
| `C|guildBlessDrop|x×1000` | 길드 축복을 켠 사람만 드롭 확률 × (100 + x)/100 (표 값엔 안 곱함) |
| `D|몬스터|아이템|ppm` | 몬스터 한 마리 처치당 그 아이템 확률(백만분율, 배율 적용, 최대 100%) |
| `M|묶음|아이템|ppm|고르는 개수` | 나만의 사냥터 몬스터 한 마리 처치당 그 아이템 확률(백만분율, 배율 적용) — 묶음 `eq`(장비)·`sc10`·`sc60`·`sc100`(주문서)은 그 묶음에서 고른 것만 굴림, `pot`(고르는 개수 0)은 늘 굴림, `rare`(보스 보상 초기화권 · 고르는 개수 0)는 모든 나만의 사냥터에서 늘 굴림 (`tables/MyHuntDropTable.csv`) |
| `B|보스|아이템|ppm` | 보스 처치 한 번당 그 보상 확률(백만분율) — 노멀 = `보스`, 하드 = `보스_h`(`tables/BossDiffTable.csv` 하드 줄 보상, 비면 노멀과 같은 표) |

## 2. 내 강화 한 번이 조작되지 않았는지 (commit-reveal)

주문서를 쓰기 **전에** 서버가 `seedHash`(= SHA256(seed))를 먼저 보여 주고, 쓴 **뒤에** `seed`를 공개합니다. 게임 안 **[내 강화 이력]** 창의 값을 넣어 돌려 보세요.

```
node verify.cjs --seed <64자리> --nonce <nonce> --hash <seedHash> --rate <성공률%>
```

- `seedHash`가 강화 전에 받은 값과 같으면 서버가 결과를 보고 seed를 바꾸지 않은 것
- `roll = floor(SHA256(seed:nonce) 앞 8자리 × 10000 / 2^32) + 1` (1~10000), `roll <= 성공률×100` 이면 성공
- 백의 주문서: `--rate <성공률> --destroy <파괴율>` — 같은 roll이 성공이 아니고 `roll <= (성공률 + 파괴율)×100` 이면 장비 파괴, 그 위면 아무 일 없음
- 어둠의 주문서가 실패했을 때의 파괴: nonce 뒤에 `-d`를 붙여 한 번 더 — `--nonce <nonce>-d --rate <파괴율>` 이 성공이면 장비 파괴

Node.js 18 이상만 있으면 됩니다(추가 설치 없음).
